# PIPER CRAFT maintenance

- Read `docs/memory/README.md`, `current.md`, `problems.md` and `task_maps.md` before working. For every new or resumed task run `python -m astra_vla.operation_memory planning-context --instruction "the complete current instruction"` and proactively examine relevant task maps and real human demonstrations. Follow `next_demo_offset` automatically to inspect older candidates; never require user selection or treat the first page as all history. A new checkout initializes local memory using `python -m astra_vla.operation_memory compact`; machine history and graphs are untracked.
- Support human object demonstrations and human robot teleoperation demonstrations. Completed recordings automatically enter the Memory index; manual selection is not required. Codex examines all relevant recordings, reviews the three views, and generates useful titles, descriptions, tags, outcome reviews and limits while keeping stable directory IDs. The legacy selector is only a focus marker, never a discovery gate. Demonstrations are visual reference, never executable replay or a substitute for fresh scene/feedback checks.
- Maintain the RGB desktop, local IK / ordinary MOVE_J and controller-native MOVE_P backends, joint jog controls, and whole-window recording.
- Explicit scene acknowledgement may end teaching on mode=2 arms using bounded MotionCtrl_1(0,0,2), with fresh RGB, fault-free stationary feedback, mode verification and stop cancellation. Never send a reset, enable/disable, replay or motion target here; failures retain ordinary pause/stop and do not open a control session. Firmware that does not exit requires separate supported manual recovery.
- Before real motion, observe fresh RGB and both arms' feedback. Startup is observation only. Retain input timeout, stop, controller-health and feedback freshness; retain entry current-pose/gripper-envelope checks in the local IK backend; local path and finger-sweep collision checks are removed at the user’s request. Controller-native MOVE_P omits local collision checks at the user’s request. Never infer physical support or permission to reset/disable an arm from historical notes.
- SDK end-effector feedback is authoritative. Local FK is for IK and robot geometry; do not compare it to, or replace, SDK pose feedback.
- Local ordinary control retains acceleration, following budgets and entry current-pose/gripper-envelope checks. Ordinary IK, joint jog, automatic joint transitions and Sleep return do not check local path or finger-sweep self-collision; telemetry/traces report path_precheck=none, path_collision_check=false and local collision_scope=entry_hold_only. Controller-native control uses actual queried controller angle bounds, TCP following budgets, and no local URDF current-pose or gripper-envelope collision checks, as requested after a user-reported false positive. State, traces and UI must reflect that omission; do not imply equivalent controller collision protection or coverage of future controller paths. Joint jog is local-only direct ordinary MOVE_J without path collision checks or TCP IK/detour.
- Opening menus, focus loss, switching arms/backends/profiles and stopping clear input; never resume old keys automatically. Do not treat UI demos or offline tests as physical acceptance.
- Observe all three RGB views, including the unselected arm's wrist camera. Moving an observation arm is a real motion and needs the same scene/feedback checks. See `docs/field_notes.md` for limited field experience.
- Keep `selective_wrist_prepare` off. Existing recovery behavior is distinct from ordinary control; see `docs/teleop.md`. Do not generalize its limited field validation to other starts or hardware.
- Update an existing problem in place, separating observation, inference, change, validation and evidence. Never record simulation, static reads or offline tests as real hardware success.
- After maintenance run `python -m astra_vla.operation_memory compact` and `python scripts/check_robot_memory.py`. Each memory page is at most 100 lines, all pages at most 260 lines, with at most 12 sessions and 8 problems.
- Keep recordings and operation evidence in ignored `runs/`. Preserve conclusions and necessary evidence before cleaning local records. Never commit credentials, private operation logs or camera recordings by default.

- Proactively maintain one or more reusable task graphs as described in `docs/task_memory.md`. Nodes/transitions need reviewed physical success evidence, including successful human teleoperation; unknown/failed/simulated cases never become successful routes. Keep self-contained case facts, reflections, strategies and limits in Memory; nodes reference durable case summaries rather than run files. SDK reference values can be embedded with limitations and are never executable waypoints.
- Before reuse, review the new instruction, objects, scene, arm roles, start state, backend, observation views, grasp, grasp depth, completion and reference limits; adapt dynamically from fresh views/feedback. Promote revisions only after new physical success. Immediately invalidate references that caused failure; correct or remove obsolete references or revoked success conclusions; cleaning run files does not invalidate durable summaries. Failed operations remain in problem memory, not task graphs.
- After each held key combination ends, show actual SDK J1–J6 and gripper width/effort/enabled state in window messages. Distinguish release readback from confirmed stationary readback, mark stale/missing data, and retain the last 32 steps in telemetry/traces. Display never sends motion or proves success.

- For each reuse, independently assess observation_views and grasp_depth as described in `docs/task_memory.md`, including visibility and occlusion from both wrists, contact depth before closing, and slip after a short lift. Unknown historical depth stays unknown.
- Command rates have no application-level translation, rotation or gripper ceiling; SDK speed percentage stays within 1–100. Detours continue after key release and retain acceleration, following and cancellation guards; they perform no path collision checks.
