# PIPER CRAFT 操作

启动 `./start.sh`，先观察三路实时 RGB，现场复核后点击“现场确认”和“进入控制”。窗口默认选择左臂及“本地 IK”方案。退出或故障后重新观察，不恢复旧按键。

右侧“方案”按钮或 Esc 菜单内的“控制方案”按钮，在“本地 IK”和“控制器原生”之间切换。点击后立即清空按键并请求停止；收到新鲜静止确认后才更新方案，失败时保留原选择。切换不自动进入控制，需重新现场确认并点击“进入控制”。原生方案支持左右臂、慢/常规/快档及 Q/E 夹爪；启动不会使能或恢复运动。

## 按键

| 按键 | 操作 |
|---|---|
| W / S | TCP +Z方向前进 / 后退 |
| A / D | TCP +Y / −Y横移 |
| Space / 左Shift | 基座 +Z / −Z升降 |
| I / K、J / L、O / P | 工具方向的抬低头、左右转、侧倾 |
| Q / E | 连续闭合 / 张开夹爪，可与运动组合 |
| 1 / 2 | 选择左右臂，先清键并等待静止 |
| Tab / 档位按钮 | 常规→快→慢循环 |
| F5 | 腕部与顶视切换，不改变运动方向 |
| F3 | 坐标、方向、时间、关节、停止结果与原始错误 |
| F1、F8、F11 | HUD、置顶、全屏 |
| Esc | 菜单与按键暂停 |
| F9 | 请求停止，实际静止结果单独显示 |

支持长按；反向键抵消，组合平移归一化。仅转向时固定配置TCP的位置；当前零偏移不等于实体指垫或瓶口位置。菜单可查看和修改按键及启动默认项。

慢/常规/快档平移目标分别5/20/100 mm/s，转向2/5/10°/s。敏感姿态、加速度或跟随预算可能使IK缩步，目标速度不等于实体速度。松键立即取消输入并暂停，不设置额外位移合格线。

右下角新增12个关节按钮：J1−/J1+至J6−/J6+，控制当前选择手臂对应关节角度减小/增大。在本地方案进入控制后，按住鼠标左键连续点动；松开、拖出按钮、失焦、打开菜单、隐藏界面、换臂、切档或停止立即清除输入，不补走旧目标。按钮不会自动进入控制，也不与TCP/夹爪输入叠加；原生末端方案下禁用，需先按既有流程切换到本地方案。

关节点动直接生成普通MOVE_J的单轴关节增量，跳过末端IK和自动绕行，慢/常规/快档目标角速度为2/5/10°/s，沿用渐进输入、关节加速度和跟随预算、目标量化、完整路径及夹爪包络自碰撞检查。该操作不固定TCP的位置或朝向；SDK末端实读仍是实读来源，关节角度边界由控制器处理。F3也保留右下角按钮，显示`joint_jog`控制状态。离线演示仅模拟关节角度，不模拟该关节变化的真实TCP轨迹。

## 画面和录像

主画面旁的小窗显示另一视角，控制按钮集中在右侧。相机过期会标明，不把缓存当实时。

任务观察应综合顶视和双腕RGB。另一臂的腕部相机也可作为辅助视角，不因当前控制臂不同就忽略；按实际视野交叉复核夹持遮挡、瓶口与杯沿高度、出水落点、瓶唇残滴及瓶底是否受桌面承托。10-25按用户建议重试：先调整左腕取景并静止，再由右臂抓瓶；左腕拍到水流入杯，用户确认本次没有新增洒水。该单次结果支持辅助观察的可用性，未量化性能提升。先查看已有新鲜画面；需要调整另一臂取景时，仍按普通动作流程观察双臂反馈、检查路径并保持停止保护。

腕相机按USB序列号绑定彩色V4L2接口，仅采集RGB；使用内核单调时钟的源时间戳，保留传输延迟，拒绝过期或重复帧，不读取深度或标定。

右侧“录制完整窗口”录下主画面、小窗、消息、F3与菜单；再次点击正常保存到 `runs/window_*/window.mp4` 和 `window.json`。`closed=true`表示文件已收尾，不证明任务成功或实际静止。关窗前先退出控制并停止录像。

## Codex 公开消息

从Codex环境启动时，窗口自动绑定当前会话，实时显示新产生的公开进展及用户指令；内部推理和工具输出不进入画面。窗口也读取 `.runtime/codex_messages.jsonl` 的显式消息。所有文字均标记 `[Codex]`，实际控制故障优先显示，文本不自动变成按键或机器人RPC。

```bash
.venv/bin/python -m astra_vla.codex_messages --session current --seq 1 '进展：已观察新画面，正在检查下一步路径。'
./start_teleop.sh --codex-messages /path/public_messages.jsonl
```

显式消息使用递增seq；自动会话从绑定时末尾开始，不重播历史。新Codex会话可运行 `python -m astra_vla.public_session` 重新绑定，窗口无需重启。消息有时效；离线Demo默认不读取正式会话或消息源。

## 控制与反馈

两种方案由同一个worker独占CAN，运行中的会话不能修改后端。SDK末端反馈直接用于输入积分、TCP读数和状态显示；不与本地FK比较或用FK替换实读。F3显示所选/运行后端、实际IK来源和检查范围。

| 方案 | 执行方式 | 本地模型范围 |
|---|---|---|
| 本地 IK（默认） | Pinocchio＋CasADi/IPOPT解算后发送普通MOVE_J | 加速度、跟随预算、完整关节路径及夹爪扫掠自碰撞；可后台绕行 |
| 控制器原生 | 位置/姿态增量经EndPoseCtrl＋MOVE_P交由控制器执行；平移可渐进调姿，夹爪使用GripperCtrl | 当前实读自碰撞与当前手臂姿态下的夹爪包络；没有未来完整关节路径预检或本地绕行 |

原生正式方案按用户选择允许平移自动调姿：每次进入通过现有CAN owner逐轴读取控制器角度范围，使用S-V1.5-8对应SDK参数做末端目标可达性计算。可行时保持朝向；触及范围时在原有转速及0.5°姿态跟随预算内渐进调整朝向，必要时缩小本次平移增量。主动转向输入不自动改写；没有可行小步或计算超时则暂停当前输入，保持会话、松键后重试，不发送失败目标。不采用URDF名义角度范围，不写入控制器限位。实际编码后的目标再次求解核验；模型解仅是目标的可行性证据，实际关节逆解/分支仍由控制器决定。此计算不包含未来关节路径、自碰撞预检或自动绕障；当前自碰撞检查仍执行。其他固件未有已验证模型时拒绝该正式入口。

原生方案保留方向/TCP换算、输入渐进、目标跟随预算、松键暂停、失焦及输入/RGB/反馈/控制器故障守护。关节速度、加速度及角度边界由控制器处理；慢档发送至多5%速度，常规/快档沿用配置的速度百分比。原生入口要求所选臂已经使能并静止于CAN位置控制；不自动使能、回位或调用本地恢复。需要准备时先使用本地方案，退出并确认静止后再切换。原生方案不受先前短程试验的20秒/5mm/2°临时预算限制；此前右臂短测不能代表左右臂长距或高速已验收。

本地 IK 方案仍检查目标量化、IK、加速度、跟随预算、完整关节路径和夹爪扫掠自碰撞。普通按键控制已取消本地关节超速和绝对角度边界检查：IK、入口保位、量化目标和路径复核不再按URDF角度上下限或J4/J5安全余量拒绝目标，也不强制余量内单向退离。关节速度及角度边界由控制器处理，`speed_percent`继续发送给控制器；控制器拒绝或报错仍停止控制。加速度及跟随距离仍可能使IK缩步，不保证实体速度。失焦、输入超时、图像/反馈过期和控制器故障仍取消控制。当前控制不含外部桌面、物体和另一臂的标定几何守护，近物动作按新RGB逐步观察。

连续小步受阻时，`config/teleop_detour.json`启用的后台规划会为一个固定TCP目标搜索另一组关节解；旋转目标为当前档位约1秒的输入量，平移同理。目标以新的SDK反馈定义，途中TCP偏离不设上限。独立规划进程不占用逐帧几何队列，普通局部目标在规划期间继续验证发送；有越过模型搜索范围趋势的候选则不继续前推。切换及完成均不额外暂停、不等待静止，沿用已发送关节目标及速度，按原加速度和跟随预算连续衔接。实际平滑性仍须实机验收。

绕行终点搜索使用URDF名义关节区间，区别于普通按键不作本地绝对角度拒绝；候选路线检查自身几何和独立轴角点。执行每个小段前重新检查新反馈到该段目标的扫掠路径，实际衔接可偏离预览直线。继续按住原组合键才执行；松键、改键、换臂、切档、失焦、输入/RGB/反馈超时及停止均丢弃路径和晚到结果，不补走旧目标。Q/E组合不自动绕行。窗口显示“后台规划”或“绕行百分比”，F3显示阶段；搜索失败、跟随停滞或控制器报错保持原停止保护。此模式同样只检查机器人自身几何，不包含桌面、物体或另一臂的环境碰撞守护。

绕行逐帧计算与发送采用各自截止时间：常规档几何计算45ms，反馈复查与SDK发送仍须在完整50ms周期内完成。超时候选不提交，连续三次超时停止；F3阶段耗时及控制记录区分几何、反馈复查、配置复查和SDK发送。绕行自碰撞布尔查询缓存夹爪扫掠几何，由Pinocchio批量检查相同碰撞对。相关失败与修复见[绕行截止时间诊断](field_notes.md)，尚未据此验收实机绕行。

入口不因角度越界单独触发恢复；普通入口保位检查发现模型自碰撞时，仍可请求有界折叠起姿恢复。依用户要求，该专用恢复取消本地URDF网格碰撞检查：不再检查恢复路径、独立轴角点、终点稳定范围或执行反馈的网格接触，也不建立或维护折叠接触包络。普通控制入口及恢复后进入按键控制前的保位检查仍有自碰撞保护；若恢复后的姿态仍触发该检查，进入控制仍会被拒绝。

恢复保留除J5上限外的原有关节边界，J5上限由控制器处理，不按URDF的1.22rad（约69.90°）拒绝或裁剪。依用户要求，起姿恢复不再设置总修正预算、单段行程预算或相对最初反馈的角度偏离预算；最初反馈仅保留作记录和逐轴试验的被动关节检查依据。目标按J2/J3最近边界及0.5°内缩计算，不再为模型接触搜索退腕路线；限内折叠起姿至少将J2抬到0.5°、J3退到-0.5°。右臂J2为负时，先用合法目标收紧到0°并全臂使能，再按上电反馈重验并分段抬肩、展肘。普通MOVE_J执行各段目标，每段交接先暂停、清轨迹并确认静止。起姿J2/J3最多3°超界的适用范围、恢复关节边界、速度、执行阶段路径跟随、图像/反馈新鲜度、控制器故障和停止守护继续执行。依用户要求，已删除使能阶段相对原路径0.75°偏离阈值（enable_settling_deg）；上电反馈偏离原路径不会单独触发停止，之后仍按上电实读重验路线。全臂使能及位置模式确认、使能到位等待、使能后的速度与超界守护保留；右臂合法起姿到位0.1°并持续0.5秒的握手条件仍执行。取消预算和该偏离阈值后，10-25右臂单次分段恢复完成；随后的入口保位因反馈变动拒绝并确认停止，反馈稳定后重入成功。该记录不代表全面冷启动或所有起姿验收。

执行反馈离开0.25°路径带时，先暂停清轨迹、确认静止，再校验剩余路线的角度边界；最多内部重规划两次，不恢复旧目标。试验性逐轴使能`selective_wrist_prepare`保持关闭，规划入口拒绝开启该已失败试验；只用普通模式全臂使能。S-V1.5-8控制器继续使用原有坐标定义的模型，不套用后续固件的关节零点偏移模型。

本轮实测及失败边界见[控制修复验收](field_notes.md)。小步控制和反馈静止不代表外部物理精度、抓持力或倒水成功。

保留兼容`native_pose_probe=true`的右臂慢档短程试验入口，其20秒、5mm/2°及关节偏离8°预算只适用于该试验。界面使用正式`execution_backend=controller_move_p`方案。历史短程实测见`runs/native_right_probe_20261020/verification.json`，界面接入及切换验证见`runs/backend_switch_integration_20261020/`。

夹爪effort为SDK参数，不是标定后的指端力。长按Q持续向0开度请求；松键按实读保持，不保证保留预紧力。持续Q时松开其他运动键也会触发暂停并按实读保位，静止复核后Q才恢复。抓牢和倒水成功必须有实物影像。

10-25实际倒水有水入杯，用户确认桌面有少量水，未达到零洒漏。持续Q和O/P侧倾完成当次搬运与出水，但不能证明物体不滑移；张开夹爪时瓶体下移，松爪前承托确认不足。顶视瓶口投影接近杯口不能代替高度视差、实际水流落点及断滴核验，恢复原SDK姿态也不保证瓶身回正。经验、失败边界与录像见[当次记录](field_notes.md)。

同日重试采用顶视和双腕交叉观察，低位试提/短移后只抬高约40mm，未出水时对位，接近出水分约3–4°观察，左腕确认水流在杯内后立即反向断流；回转后观察残滴，再撤离、分步降放/开爪并试退。用户确认本次没有新增洒水，最终瓶子直立、夹爪退开并停止确认。具体位姿与时长依赖现场，不是可盲放的动作脚本，也不证明无微小滑移、倒水量或通用零洒漏。[重试证据与可复用经验](field_notes.md)。
