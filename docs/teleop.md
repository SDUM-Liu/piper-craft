# PIPER CRAFT 操作

启动 `./start.sh`，先观察三路实时 RGB，现场复核后点击“现场确认”和“进入控制”。窗口默认选择左臂及“本地 IK”方案。退出或故障后重新观察，不恢复旧按键。

“现场确认”（菜单中的“现场复核后确认停止”）现在会自动检查双臂示教模式。先以新鲜、无故障反馈确认双臂持续静止；若发现 `TEACHING_MODE(0x2)`，仅对该臂发送 SDK `MotionCtrl_1(0, 0, 2)` 结束示教记录，最多尝试约2秒，再确认模式已稳定离开示教且双臂仍静止。过程中检查三路 RGB、双臂姿态/使能状态、控制器故障及停止取消；写入后的失败沿用双臂暂停与停止确认。结果证据在 `runs/teach_exit_*/result.json`。

这一步不发送运动目标、轨迹回放、使能/失能或复位，也不自动进入控制；MIT、CPV或主从等其他控制模式仍拒绝自动接管。若固件保持示教模式，界面说明退出未确认并保留停止；需要按有当次可靠支撑事实的人工恢复流程处理，现场确认不会自动升级为复位。该功能的离线模拟不代表实机退出示教已验收。

10-27起仅启用本地IK/普通MOVE_J；原生MOVE_P和旧native_pose_probe在界面与RPC入口均禁用。F6或右侧/菜单“坐标”按钮在“基坐标”和“运动坐标”之间切换。切换立即清空按键、取消自动动作并请求停止，确认静止后才更新模式；失败保留原模式，不自动进入控制。重新现场确认后再显式进入控制。

## 自动回到 Sleep

在本地方案为所选臂进入控制后，先用顶视和双腕实时 RGB 复核已放稳手中物体、夹指与桌面/邻物间隙及回位空间，再点击右侧“回 Sleep”。每次只回所选臂，另一臂不自动运动；需要双臂回位时逐臂操作。启动、进入控制、退出和停止均不会自行触发回位。原生方案已禁用。

目标优先读取本机 `config/sleep_pose.json`，不存在时兼容 `../sleep_pose.json`。新部署复制 `config/sleep_pose.example.json` 为 `config/sleep_pose.json`，填入经本机确认的六个 SDK 整数关节目标，单位为 0.001°；支持 `arms.left/right.joints_raw` 及旧 `arms.left_piper/right_piper.joints_raw`。未配置、格式错误或非整数会拒绝请求，示例中的 null 不会被当成零位。标定文件仅存本机，不提交公开仓库；会话中改动目标配置会触发停止。

回位先清键、暂停并等待连续静止反馈，再校验当前位置和固定目标的关节数据，以普通 MOVE_J 分步执行，不检查本地路径自碰撞或夹爪扫掠包络。沿用请求时档位的 SDK 速度百分比、关节加速度和跟随预算，每步从新反馈重验目标、加速度和跟随；不会继承自动绕行的100%快速参数。回位无需长按，但需要窗口保持聚焦、输入心跳、三路 RGB 和双臂反馈持续新鲜。Esc菜单、运动/夹爪键、切档、换臂、切坐标、失焦或停止取消回位，旧规划不能恢复；超时、跟随停滞或夹爪开度变化会暂停/停止并报告原因。

六关节 SDK 实读均距目标不超过0.1°，且后续连续0.5秒静止确认后，状态 `sleep_return.state` 才为 `completed`。不从本地 FK 生成或核对 SDK 末端实读；状态、进度、目标及反馈写入原有控制记录。到位保持使能，不附带夹爪开合、失能或复位；结束前的既有夹爪运动仍按普通暂停流程冻结。回位不检查机器人自身、桌面、物体或双臂互碰，控制器也没有由本软件验证的同等保护。10-27左臂曾在旧路径检查启用时完成单次回位，右臂旧路径检查拒绝；移除检查后的行为只有离线验证。

## 按键

| 按键 | 操作 |
|---|---|
| W / S | 基坐标±X；运动坐标为工具前/后（Piper ±Z） |
| A / D | 基坐标±Y；运动坐标为工具左/右（Piper ±Y） |
| Space / 左Shift | 基坐标±Z；运动坐标为工具上/下（Piper ∓X） |
| I / K | 绕所选坐标−Y / +Y旋转 |
| J / L | 绕所选坐标+Z / −Z旋转 |
| O / P | 绕所选坐标−X / +X旋转 |
| F6 / 坐标按钮 | 先停止，再切换基坐标 / 运动坐标，不自动进入控制 |
| Q / E | 连续闭合 / 张开夹爪，可与运动组合 |
| 1 / 2 | 选择左右臂，先清键并等待静止 |
| Tab / 档位按钮 | 常规→快→慢循环 |
| F5 | 腕部与顶视切换，不改变运动方向 |
| F3 | 坐标、方向、时间、关节、停止结果与原始错误 |
| F1、F8、F11 | HUD、置顶、全屏 |
| Esc | 菜单与按键暂停，取消自动回位/绕行 |
| F9 | 请求停止，实际静止结果单独显示 |

支持长按；反向键抵消，组合平移归一化。仅转向时固定配置TCP的位置；当前零偏移不等于实体指垫或瓶口位置。菜单可查看和修改按键及启动默认项。

慢/常规/快档平移目标分别5/20/100 mm/s，转向2/5/10°/s。敏感姿态、加速度或跟随预算可能使IK缩步，目标速度不等于实体速度。普通控制松键立即取消输入并暂停，不设置额外位移合格线；自动绕行触发后松键继续，Esc或F9取消。

右下角新增12个关节按钮：J1−/J1+至J6−/J6+，控制当前选择手臂对应关节角度减小/增大。在本地方案进入控制后，按住鼠标左键连续点动；松开、拖出按钮、失焦、打开菜单、隐藏界面、换臂、切档或停止立即清除输入，不补走旧目标。按钮不会自动进入控制，也不与TCP/夹爪输入叠加；原生末端方案已禁用。

关节点动直接生成普通MOVE_J的单轴关节增量，跳过末端IK和自动绕行，慢/常规/快档目标角速度为2/5/10°/s，沿用渐进输入、关节加速度、跟随预算和目标量化，不检查路径及夹爪包络自碰撞。该操作不固定TCP的位置或朝向；SDK末端实读仍是实读来源，关节角度边界由控制器处理。F3也保留右下角按钮，显示`joint_jog`控制状态。离线演示仅模拟关节角度，不模拟该关节变化的真实TCP轨迹。

## 画面和录像

主画面旁的小窗显示另一视角，控制按钮集中在右侧。相机过期会标明，不把缓存当实时。

侧栏按工具栏、TCP按键（含标题与停止提示）、关节点动面板分区预留高度；最小1100×700窗口与切档提示状态下，各区背景、文字及点击区域也不得重叠。小窗按剩余空间缩放，TCP按键区与关节面板至少保留8像素间隔。

任务观察应综合顶视和双腕RGB。另一臂的腕部相机也可作为辅助视角，不因当前控制臂不同就忽略；按实际视野交叉复核夹持遮挡、瓶口与杯沿高度、出水落点、瓶唇残滴及瓶底是否受桌面承托。10-25按用户建议重试：先调整左腕取景并静止，再由右臂抓瓶；左腕拍到水流入杯，用户确认本次没有新增洒水。该单次结果支持辅助观察的可用性，未量化性能提升。先查看已有新鲜画面；需要调整另一臂取景时，仍按普通动作流程观察双臂反馈、检查路径并保持停止保护。

Codex判断物体优先执行 `python -m astra_vla.observe --output /tmp/piper_observation`，直接查看三路PNG和源时间戳/身份元数据。PNG保留采集流原分辨率与解码RGB像素，不经窗口缩放或JPEG再压缩；不会凭空提高传感器采集分辨率。界面仍使用轻量JPEG预览，桌面截图用于检查按钮和状态。

腕相机按USB序列号绑定彩色V4L2接口，仅采集RGB；使用内核单调时钟的源时间戳，保留传输延迟，拒绝过期或重复帧，不读取深度或标定。

右侧“录制完整窗口”录下主画面、小窗、消息、F3与菜单；再次点击正常保存到当前任务的 `videos/window_*/window.mp4` 和 `window.json`。`closed=true`表示文件已收尾，不证明任务成功或实际静止。关窗前先退出控制并停止录像。

## 任务级归档

新控制会话和整窗录像共用一个 `runs/task_时间_ID/`。`task.json`登记任务名称、指令及材料清单；控制与起姿恢复分段位于 `segments/teleop_*/`，整窗录像位于 `videos/window_*/`。各分段仍保存原始反馈和收尾结果，任务显式结束后另写一份总 `result.json`。换臂、停止、切后端和重开窗口都沿用当前任务，不自动结束或判成功。Memory对同一任务只更新一条摘要，故障仍独立进入问题页。

启动只观察时不创建任务。可在菜单“新建任务”，也可直接开始控制/录像时自动创建未命名任务。菜单“结束任务（结果未知）”要求先退出控制并保存录像；归档只管理文件，不发送停止、运动、使能或复位命令。结束后，下次控制/录像自动进入新任务。当前任务绑定保存在 `.runtime/active_task.json`，因此应在更换实体任务时显式结束旧任务。

Codex执行实体任务前可用下列接口填写名称及完整指令；同一任务后续动作不重复begin。成功必须由当次实物复核或用户确认，不能从停止、恢复到位或录像收尾自动推断。失败/中止须先复核并将自包含教训写入summary，finish保存简短Memory后删除整个任务材料，不备份；unknown保留未知，不自动删除。人类示范继续保留稳定原目录ID，不搬入任务分段。旧版平铺材料仍可读取，新结构不自动移动正在使用的旧记录。

```bash
python -m astra_vla.task_archive begin --name '收纳羽毛球' --instruction '本次完整实体任务指令'
python -m astra_vla.task_archive status
python -m astra_vla.task_archive finish --outcome unknown --summary '当前可确认的事实与未完成项'
# 实物完成复核后：
python -m astra_vla.task_archive finish --outcome success --basis user_confirmation --summary '当次确认的完成事实与边界'
# 失败/中止在完成必要复核和知识提炼后：
python -m astra_vla.task_archive finish --outcome aborted --reviewed --summary '观察事实、教训、改进及验证边界'
```

任务结束时仍在写入的分段/录像会阻止收尾；写入进程异常退出后可结束为unknown，清单标明interrupted，不冒充正常停止。旧进程需按原有停止/控制权交接流程重载新版；归档功能不会自行重启设备服务。离线Demo录像另存 `runs/offline_windows/`，不绑定真实任务。

## 人类动作示范

“人类示范 / Codex 参考”面板支持亲手操作物体和遥控机械臂两种示范。三路 RGB 独立录制，保存带时间的双臂 SDK 反馈及界面输入；保存后自动进入Memory候选，无需手动选择。Codex主动查看相关示范、分析并生成名称/描述、复核结果，仅成功案例支持任务地图；原选择按钮仅作重点标记。亲手示范先退出控制并确认静止，录制期间禁止当前窗口进入控制；遥控示教沿用现有控制保护。详见[示范录制与参考](demonstrations.md)及[任务地图](task_memory.md)。

## Codex 公开消息

从Codex环境启动时，窗口自动绑定当前会话，实时显示新产生的公开进展及用户指令；内部推理和工具输出不进入画面。窗口也读取 `.runtime/codex_messages.jsonl` 的显式消息。所有文字均标记 `[Codex]`，实际控制故障优先显示，文本不自动变成按键或机器人RPC。

```bash
.venv/bin/python -m astra_vla.codex_messages --session current --seq 1 '进展：已观察新画面，正在检查下一步路径。'
./start_teleop.sh --codex-messages /path/public_messages.jsonl
```

显式消息使用递增seq；自动会话从绑定时末尾开始，不重播历史。新Codex会话可运行 `python -m astra_vla.public_session` 重新绑定，窗口无需重启。消息有时效；离线Demo默认不读取正式会话或消息源。

每段接受的按键组合结束后，消息区自动显示SDK六关节角度、夹爪开度/effort/使能，附步骤编号、按键及持续时间。先显示松键实读，再以既有静止确认更新同一条；组合改变后继续运动不会拿下一步终态冒充前一步终态。反馈缺失/过期明确显示不可用，未发送动作目标也会标注。RPC与控制记录保存最近32步，消息不触发运动，effort不是标定后的指端力；人工遥控与Codex按键都适用。

## 控制与反馈

本地IK/普通MOVE_J由一个worker独占CAN。SDK末端反馈直接用于输入积分、TCP读数和状态显示，不用本地FK替换实读。原生MOVE_P和旧短测入口均在准备/使能/SDK发送之前拒绝，状态只公布本地后端。模式切换不修改控制器物理角度范围。

本地 IK 方案检查目标量化、IK、加速度、跟随预算；10-27按用户要求移除普通按键、关节点动、自动关节过渡及回Sleep的本地路径/夹爪扫掠自碰撞检查。10-28按用户要求取消入口反馈数据与夹爪包络自碰撞检查。状态/记录标记`path_precheck=none`、`path_collision_check=false`、`collision_scope=none`；过渡/回Sleep计划自身标记`scope=none`。控制器没有经本软件验证的等效碰撞保护。普通按键控制已取消本地关节超速和绝对角度边界检查：IK、入口保位、量化目标和路径复核不再按URDF角度上下限或J4/J5安全余量拒绝目标，也不强制余量内单向退离。关节速度及角度边界由控制器处理，速度配置仅要求正数且有限，不再按档位设置平移/转向/夹爪速度的人为上限；`speed_percent`允许SDK协议的1–100整数范围并继续发送给控制器；控制器拒绝或报错仍停止控制。加速度及跟随距离仍可能使IK缩步，不保证实体速度。失焦、输入超时、图像/反馈过期和控制器故障仍取消控制。当前控制不含外部桌面、物体和另一臂的标定几何守护，近物动作按新RGB逐步观察。

连续小步受阻时，`config/teleop_detour.json`启用的后台规划会为一个固定TCP目标搜索另一组关节解；旋转目标为当前档位约1秒的输入量，平移同理。目标以新的SDK反馈定义，途中TCP偏离不设上限。独立规划进程不占用逐帧几何队列，普通局部目标在规划期间继续验证发送；有越过模型搜索范围趋势的候选则不继续前推。绕行触发后自动执行，规划和执行期间无需持续长按；规划期间松键不再生成普通局部目标。切入时沿用已发送关节目标与速度，保持原关节加速度约束；执行使用独立的快速过渡配置，默认控制器速度100%、关节跟随预算6°，不受原按键TCP速度限制。每帧仍按跟随预算生成小段，检查加速度与跟随，不做路径自碰撞检查。若原键已松开，到点后暂停并等待静止确认；仍按住原键则返回普通控制。实际过渡速度和平滑性须实机验收。

绕行终点搜索使用URDF名义关节区间，区别于普通按键不作本地绝对角度拒绝；候选及执行小段均不检查自身几何或独立轴角点；发送前按新反馈重验编码目标、加速度和跟随，实际衔接可偏离预览直线。松键继续自动过渡；改键（含松开后重新按键）、Esc菜单、换臂、切档、失焦、输入/RGB/反馈超时及F9停止均丢弃路径和晚到结果，不补走旧目标。窗口保持焦点并持续发送输入心跳才可执行，空按键心跳不等于取消绕行；菜单通过`cancel_detour`显式取消。Q/E组合不自动绕行。窗口显示“后台规划”或“绕行百分比”，F3显示阶段；搜索失败、跟随停滞或控制器报错保持原停止保护。此模式无路径碰撞检查，也无桌面、物体或另一臂的碰撞守护。

绕行逐帧计算与发送采用各自截止时间：常规档几何计算45ms，反馈复查与SDK发送仍须在完整50ms周期内完成。超时候选不提交，连续三次超时停止；F3阶段耗时及控制记录区分几何、反馈复查、配置复查和SDK发送。按10-27新指令，关节过渡已不执行路径自碰撞查询。历史诊断原始记录已按10-27留存要求清理，尚未据此验收实机绕行。

10-28按用户要求移除本地起姿自碰撞检查：当前关节及量化关节、当前夹爪及未验证开度包络均不查询URDF碰撞，也不因该检查触发折叠恢复。入口仍核查有限反馈、SDK状态/模式、连续静止、准备期间数据变化及配置一致性。路径自碰撞检查沿用既有取消状态，状态和记录统一标为`collision_scope=none`。此变更不表示控制器提供同等自碰撞保护。历史恢复实现保留作兼容，不能据历史模型拒绝认定当次实体碰撞。
