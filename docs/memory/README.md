# 操作记忆维护规则

目的：让后续实体操作复用事实和修复经验，持续改进当前控制框架。这里是有界操作记忆，不代表模型权重训练或无人监督代码修改。

## 必须遵循的维护顺序

1. 操作前读 `current.md`、`problems.md`、`task_maps.md`，用新指令运行 `operation_memory planning-context` 自动查看相关地图及人类示范；无需手动选择。历史反馈不能代替实时设备状态。
2. 实际动作保存输入、目标、反馈与需要的影像；静态观察不创建操作经历。
3. 收尾自动按任务合并当前控制记录为一条摘要；任务归档见`docs/teleop.md`。问题原位更新，保留具体失败和验证范围。
4. 修改后运行相关离线检查；实机结论必须另有实际动作和影像。
5. 删除过期状态，合并重复原因，保留尚未解决的问题；随后compact/check。
6. 用户10-27要求：失败/中止操作在完成当次必要复核和知识提炼后，删除其录像、图像、轨迹、按键/反馈日志和结果文件；不归档或备份。只保留自包含的简短教训与改进边界，清除流水摘要和失效路径。成功材料与用户保留的人类示范不按失败处理，未知结果不擅自改判。

## Codex 主动维护的规划参考

- 每个实体任务先按常识核对物体功能、操作方向（羽毛球球头先入筒）、承托和释放，规划下一组1–3个动作，逐步列前提/坐标轴/细节/观察/完成与停退判据；执行后更新。物体观察优先用 `astra_vla.observe` 直接读三路源PNG，截图只用于UI。
- 自动查看成功地图及完整真实示范；新录制会刷新索引。对缺名/描述的示范查看三路画面，主动生成可检索名称、描述、标签、结果与适用边界，保留稳定目录ID。
- 只从真实成功复核的任务/人手或遥控示范提炼元操作节点与地图；失败/未知/仅录像收尾或停止正常不提升为成功。长期保存自包含的案例事实、反思、策略、未知处和适用边界；节点和连接关联Memory内的案例总结，不指向运行文件。必要SDK参考值内嵌并说明限制，不形成可执行轨迹。
- 新输入/现场复用前评估目标、物体、场景、双臂角色、起姿、后端、观察视角、抓持、抓夹深度、完成条件及参考限制；执行中根据新RGB/反馈动态调整。新调整只有经真实成功复核后才进入长期地图。
- 腕部辅助视角与抓夹深度是独立必评项：逐阶段写明顶视/操作腕/另一腕看清什么和遮挡，未选中臂也主动看；关键接触/高度不清先暂停、补观察，移动观察臂仍按普通真机要求。
- 闭爪前核查物体进入双指的程度、两侧接触、夹持高度及指尖间隙，避免仅指尖浅夹，也不盲推到底；试提/短移后复查滑移/转动。开度/effort/已提起不能证明夹深；无标定不报毫米，历史未测就记未知，不补写成功。详见任务地图规则。
- 清理/覆盖运行记录不删除长期经验，也不要求补回原文件。参考导致失败立即删除该图并清除复用评估；成功判定被推翻主动撤销，过时参考修正或删除。compact只检查总结结构与显式期限。失败教训仍进问题页，不保存失败路线。
- 清理前确认事实、反思和适用边界已总结；文件路径不算经验。现场复用评估仍依赖当次新RGB/双臂反馈，短期材料失效只要求重评现场。
- `task_maps.json`为本机有界数据，`task_maps.md`为短索引；完整规则与维护接口见 [任务地图](../task_memory.md)。这不是权重训练或已量化的规划提速。

## 证据标签

- **观察**：实际日志、反馈、RGB或用户当次确认的事实。
- **推断**：原因假设；未验证时必须明确，不写成观察。
- **修改**：具体代码、参数或操作策略变化。
- **验证**：已完成的测试及边界；软件通过不等于实机通过。
- **证据**：可选的当次材料路径，用于复核；失效引用及时清理，观察结论和反思独立保留，不以文件留存作为经验有效条件。

状态：open、software_verified、hardware_verified、resolved。禁止自动从离线测试推断硬件成功。

## 长度与整理

`current.md`最多12次摘要，`problems.md`最多8项；每个Markdown≤100行，总计≤260行。自动写入会有界压缩；同一问题更新替代旧条目。`state.json`仅为这些简短摘要的结构化来源，不堆叠原始日志。

```bash
.venv/bin/python -m astra_vla.operation_memory compact
.venv/bin/python scripts/check_robot_memory.py
.venv/bin/python -m astra_vla.operation_memory problem sdk-pose --observed '实际现象' --inference '待验证原因' --change '具体修复' --validation '实际检查' --evidence 'runs/当前证据' --status software_verified
```
